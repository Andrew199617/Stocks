# Stocks — Owner's Earnings DCF Sweep

Andrew's project (started 2026-10-12): screen the Russell 3000 for stocks that can clear his hurdle rates.

## Scope
- Universe: top 3,000 US-listed operating companies by market cap (free reproducible Russell 3000 equivalent — see `universe_notes.md`), filtered to **market cap < $40B**.
- Size on 2026-10-12: **2,617 companies** (`universe.csv` / `queue.json`). APP is the pilot and an exception — its market cap is >$40B, it stays as the worked example only.
- Cadence: two pass-1 workers (`dcf-hourly-sweep`, `dcf-sweep-parallel` — the names are historical) each firing every 15 minutes; measured throughput is what matters (audit round 1: ~1.7 companies/hour). Full sweep: weeks, not days. A daily HTML ranking is sent once a day (`dcf-daily-ranking`, ~7pm ET) built from whatever is completed so far — it gets more useful every day, it is not held until the sweep finishes.
- Queue order: Andrew's watchlist (under $40B) first, then descending market cap. A universe rebuild (`build_universe.py`) keeps every surviving name's queue entry verbatim (status, claim stamp, completion date, notes); only the order changes.

## Per-company folder: `~/workspace/stocks/<TICKER>/`
What is committed (2026-10-16): the judgment record (`financials_history.csv`, `dcf_numbers.json`, `judgment.json`, `analysis.md`, `score.json`, `key_numbers.md`, `ttm.json`, `second_pass.md`) and the SEC files (`fundamentals.json`, `statements.json`, `segments.json`, `profile.json`). The SEC files go through `_stable.py`, which leaves a file untouched when nothing but its run date would change, so a file's `as_of` is the day its content last changed. The Nasdaq caches (`prices.json`, `street.json`, `live.json`) are gitignored; `python _system/refresh.py` recreates them on any machine.
- `financials_history.csv` — up to 10 fiscal years from SEC EDGAR 10-Ks (revenue, net income, OCF, capex, D&A, SBC, FCF, owner's earnings ×2, shares, net debt). v5 adds `capex_tag` / `sbc_tag` columns recording which EDGAR tag supplied each period.
- `dcf_numbers.json` — engine output: base owner's earnings/share, growth history, five-scenario IV at 10/12/15% discount, implied IRR, tier by numbers, diagnostics, fragility flags, and (v5) `data_gap` — non-empty means the engine refused to emit a tier.
- `judgment.json` — the agent's judgment inputs only (v5): name, sector, moat_score, moat_justification, `moat_for` / `moat_against` (short pillar strings from the MOAT section's FOR/AGAINST lists), probs_used, one_liner, confidence, tier_override + tier_override_reason, in_scope_under_40b.
- `analysis.md` — the agent's written work: what the business is, owner's earnings quality, maintenance-vs-growth capex judgment, moat/risks/red flags, whether historical growth is repeatable, forecast adjustments and why, final verdict.
- `score.json` — machine-readable final score for the daily HTML, **built by `make_score.py` from `dcf_numbers.json` + `judgment.json`** (never hand-written): ticker, name, price, market_cap_b, sector, base_oe_per_share, implied_irr, tier, iv_at_15, upside_at_15_pct, confidence (low/med/high), one_liner, analysis_date, plus `moat_for` / `moat_against` when judgment.json carries them. v5.4 adds `irr_bear` / `irr_bull` / `tier_bear` / `tier_bull` (the band), `iv_at_20` / `iv_at_25` (the Tier A / S hurdle prices), `f_subtype`, `irr_at_floor`, `model_fit` (modeled | misfit), `alert_eligible` (+ `alert_suppressed_reason`) — the gate for a name ENTERING Tier S/A — and `exit_alert_eligible` (+ `exit_alert_suppressed_reason`) — the gate for one LEAVING it (medium+ confidence, not a sector misfit, tier not existing only because an override fills a data gap; an IRR at the floor or a tier-override downgrade does not suppress an exit) —, `engine_release`, and a `second_pass` object when judgment.json carries one.
- `fundamentals.json` — **v5.4, `fundamentals.py`**: the filing-direct statements a reader needs but the engine does not — profile (SIC, fiscal year end, filer category, latest 10-K/10-Q with EDGAR links), up to 10 fiscal years of income statement / cash flow / balance sheet lines with margins, growth, per-share figures, ROE and an ROIC proxy, the last 12 fiscal quarters (3-month facts where filed, otherwise YTD − prior YTD; Q4 = FY − 9M; each marked `derived`), and the TTM. Banks get revenue = net interest income + noninterest income. Display and forensic evidence only — nothing here feeds the valuation. Committed and rewritten only when its content changes: the dividends block's price-dependent figures (price, market cap, yields) do not count, and `build_site.py` reprices that block at the latest close in `prices.json` when it builds the page.
- `prices.json` — **v5.4, `prices.py`, gitignored cache**: ten years of closes from the Nasdaq historical API (daily for the last year, weekly and monthly for the window, all returned by one request) plus return / drawdown statistics and a rolling store of the last five intraday sessions (Nasdaq's intraday endpoint returns only the latest session, so the 5-day chart is built up across runs). Feeds the company page's price-vs-value chart and the live repricing.
- `segments.json` — **v5.4, `segments.py`**: revenue / operating income / assets (and for banks net interest income, deposits, loans) by business segment, product and geography, from the filing's XBRL instance; annual (10-K) and quarterly (10-Q) tables with growth and share of total.
- `statements.json` — **v5.4, `statements.py`**: the full standardized income statement, balance sheet, cash-flow statement and derived metrics over the company's whole companyfacts history — every fiscal year, every derivable quarter (direct three-month facts where filed, else YTD − prior YTD, Q4 = FY − 9M, marked derived) and the TTM — with growth arrays and indent / total flags for the page's statements viewer. Served on demand by the site as `data/<T>.statements.json`; never embedded in the attachment. `--all` checks the small EDGAR submissions feed first and re-fetches only names with a newer filing (or whose file companyfacts had not caught up with yet).
- `profile.json` — **v5.4, `profile.py`**: the company page's About block (10-K Item 1 Business prose with its accession, SIC, headquarters, filer category, fiscal year end, employees with the 10-K sentence as evidence, first SEC filing, website) and the filing feed (latest 10-K / 10-Q / 8-K with plain-English item descriptions and links). `--all` rebuilds it only when the EDGAR filing feed changed (a new accession number, even on an already-seen filing date) or its last build was degraded (a source that failed is retried on the next run), and rewrites it only when its content changes.
- `street.json` — **`profile.py`, gitignored cache (2026-10-16)**: the Street block split out of profile.json (Nasdaq analyst endpoints: consensus, mean / low / high targets, monthly rating history, covering brokers, quarterly + annual EPS consensus with estimate counts and revisions, EPS actual-vs-consensus history, estimate momentum, next earnings date, forward PEG — third-party data, labelled as such, never an input to the valuation) plus Nasdaq's market summary. `--all --max-age-days 7` re-pulls it once it is a week old or when its last pull was degraded, and `--street-only` re-pulls it with no EDGAR request; `build_site.py` merges it back into the page record. Individual analyst names and track records (TipRanks) are paid data and are not included.
- `live.json` — **v5.4, `reprice.py`, gitignored cache**: the scored run's five scenario paths and weighted path repriced at the last close — live IRR, tier, bear→bull band, upside, market cap — next to the scored figures and the delta. Only the price moves; base, growth and probabilities are the agent's. A stock split since scoring is found from the split-adjusted closes and divided out of the run's per-share figures (`split_factor`, `basis_check`); a basis that cannot be checked or explained writes no live.json. An agent tier override carries over only from a score.json built from the same engine run. Absent for Tier F names.

The page headline and the ranking's default sort use the live figure; the scored figure (the agent's verdict date) stays beside it. A live.json whose close predates the scored analysis (Nasdaq posts a session's close hours after it ends, so a name scored today can have only yesterday's close) is not shown: the scored figures stay current, marked "live pending", until a close after scoring arrives. ## v5 tooling (2026-10-13; round-2 hardening 2026-10-14)
- `queue.py claim|done|block|requeue|reap` — the ONLY way workers touch `queue.json`: file-locked (`_lock.py`: fcntl, or msvcrt on Windows), atomic writes, 90-minute claim lease. `claim` runs the reaper first, under the same lock (round-2: no job ever called reap, so crashed claims stuck forever). `block <TICKER> --stdin` reads the reason from stdin (a quoted shell argument mangles `$` amounts); a reason starting with `DATA_GAP` lands in the separate `blocked_data_gap` status — the list awaiting override decisions — vs `blocked_no_data` for filings that don't exist yet.
- `ttm.py <TICKER>` — TTM owner's earnings (OCF, capex, SBC, diluted shares) computed in code from EDGAR 10-Q YTD facts (FY − prior YTD + current YTD), JSON out with every input shown, and the same JSON saved to `<TICKER>/ttm.json` as the base pin's provenance. Agents never hand-compute TTM again. Day counts are inclusive (a filled annual leg is exactly the override value, matching the engine); leg matching tolerates start dates shifted a few days; a never-filed capex hard-blocks (exit 3) unless an override fills it — no more zero-fill-with-warning.
- `make_score.py <TICKER>` — builds `score.json` (above). Refuses when `dcf_numbers.json` has a `data_gap`, when judgment/probabilities don't match the engine run, or when a tier override lacks a reason — and (round-2) when the engine output is pre-v5, when its `content_hash` is missing/mismatched, when an override is negative or out of band without an `ack_reason`, when a pinned base differs from `ttm.json` by >0.1% without a declared `base_override`, when a 20-F/40-F filer has no applied `ads_ratio`, or when `in_scope_under_40b` contradicts the computed market cap. Confidence is clamped to medium under WIDE_SCENARIO_SPREAD (`confidence_capped: true`).

**Override registry** (`_system/overrides_registry.json`, written only by `make_score.py`): on every score, the ticker's entries are **replaced wholesale** and re-derived from that run (round-2: the old upsert left stale entries behind when an override was removed). One entry per (ticker, field) for every judgment override the engine applied, carrying the override itself (value, kind, source, reason, date) and its measured impact **on the base the final run actually used**. The registry also records every other judgment call a run embodies, each as an entry with an `event` field: `tier_override` (with tiers + reason — the ranking badges these on the row and detail page), `manual_price`, `base_override`, `gterm` (non-default terminal growth), `cik` (non-default CIK), and `ads_ratio`. Each entry records `base_used` — `"ttm"` when the score's base was a TTM pin via `--base-oe-ps`, else `"median_3y"` — plus the base OE/share without → with the override on that basis, the % change in the base, the weighted IRR without → with and its change in percentage points, all measured on the final run's exact configuration (same moat/probs/offsets/mults/gterm and the same base pin) with only the overrides toggled off, and `unblocks_tier`: true when the override covers a data gap in the last 3 fiscal years, i.e. it is the only reason the company has a tier at all. `unblocks_tier` entries are the judgment calls that matter most, however small the dollar effect — review those first. The identical block is stored in `score.json` as `override_impact` and rendered on the company's page in the daily ranking; the engine's own `dcf_numbers.json` impact block is measured on the engine-native base and is NOT the headline figure when a TTM pin is in force.

## Scenarios, probabilities, and the moat-driven fade (v3, 2026-10-12)
- **Five scenarios** every time: super bear, bear, base, bull, super bull — each with an assigned likelihood (must sum to 100%). Defaults 10/25/30/25/10, growth-start offsets −12/−5/0/+5/+12pp vs the capped historical base growth, owner's-earnings level multipliers 0.75/0.90/1.00/1.10/1.25. The agent may skew probabilities (and, with a written reason, offsets/multipliers) to the company's evidence. The headline value is the **probability-weighted** IV/IRR from the probability-weighted cash-flow path.
- **Moat score 0-10, justified in writing** (specific pillars FOR, specific erosion forces AGAINST — no generic claims). Rubric: 9-10 wide/durable, 7-8 strong, 5-6 moderate/narrow, 3-4 weak, 0-2 none.
- **The moat sets the fade.** Growth fades linearly from the scenario start rate to the 2.5% terminal rate over the Competitive Advantage Period **CAP = clamp(2 + 1.3 × moat, 2, 15) years** — moat 0 fades in ~2 yrs, moat 5 in ~8.5 yrs, moat 10 gets the full 15-yr projection. A high starting growth rate with a low moat score gets faded hard, by design.
- Workflow per company: preliminary engine run → research → score moat + set probabilities → final engine run with `--moat --probs [--offsets --mults]`.

## Scoring — hurdle tiers (probability-weighted implied IRR from the owner's-earnings DCF at current price)
- **S: ≥25%** — exceptional
- **A: 20–25%** — clears the 20% level
- **B: 15–20%** — clears Andrew's 15% hurdle
- **C: 10–15%** — below hurdle
- **D: <10%**
- **F: no positive conservative owner's earnings on the base actually used** (the 3-yr median, or the TTM pin) — a DCF on owner's earnings can't support any hurdle; flagged, not forced. v5.4 splits it: `sbc_exceeds_cash` (OCF − capex is positive but SBC consumes it) vs `no_cash_generation`.
- **Band (v5.4):** the bear-case and bull-case tiers are reported next to the headline (`tier_bear` → `tier_bull`); when they differ the run carries `TIER_BAND` and any position is sized to the bear end. The headline stays the weighted IRR.

The engine's tier is the *starting* point. The analyzing agent may move the final tier in `score.json` **only** with a written reason in `analysis.md` (e.g. historical growth was one-off, capex is really all maintenance, balance-sheet risk). Numbers tier and final tier are both kept.

## Owner's earnings definitions (standardized, see `dcf_engine.py`)
- Conservative: Operating Cash Flow − total capex − stock-based comp.
- Maintenance version: Net income + D&A − min(capex, D&A) − increase in net working capital (ex cash/debt).
- SBC is always treated as a real cost in the conservative/base case.

## Fixes & lessons (read before changing the engine)
- **2026-10-18 — Market cap ignored the ADS ratio (Andrew's decision, approving the fix Codex's PR #3 review surfaced; spec in `ADS_MARKET_CAP_SPEC_DRAFT.md`).** The engine scaled per-share figures to the ADS basis but computed `market_cap_est` as price × ordinary shares, overstating the traded cap by exactly the ads_ratio whenever one applied: TLK printed $1,092.66B against a true ~$10.9B and was blocked unscored because make_score's computed-scope gate (correctly) refused the worker's in-scope claim; PAC recorded $103.03B vs ~$10.30B; FMS (ratio 0.5) was *understated* 2×, which is why the fix divides rather than special-casing ratios > 1. Fix: `market_cap_est()` in `dcf_engine.py` computes price × shares ÷ ads_ratio (the universe-screener fallback is already a traded cap and is never rescaled); `make_score.py` derives `market_cap_b` and the scope gate from `market_cap_est`, so it follows with no change there; `reprice.py`'s live cap uses the same helper on its split-adjusted share count, so live.json's cap and scope flag stay on the scored basis; `fundamentals.py`'s dividends block follows the same basis (ratio recorded in the block from `dcf_numbers.json`; build_site backfills it into legacy blocks when repricing): the yield denominator divides by the ratio and the dividend-yield numerator scales by it — before this, an ADS filer's displayed yields were off by exactly the ratio (FMS buyback/shareholder yields 2× too high at ratio 0.5; LTM's dividend yield shown 0.0010% for a true 2.04% at ratio 2000). No ratio / ratio 1 is bit-identical to the old formula, and tiers/IRRs never move — per-share figures were already ADS-scaled; only the recorded cap and scope flag were wrong. Test: `test_market_cap_ads_ratio` in `_system/tests/test_engine_math.py` (fails on the old code). The affected ADS names are re-scored as separate data PRs.
- **2026-10-14 — Engine release 5.4 (whole-engine formula audit; `_system/tests/test_engine_math.py` proves 74 scored folders reproduce bit-for-bit through the refactored math, so every change below is deliberate).** (1) **Dilution was double-counted** (audit round-1 "Model design", never fixed): the ±5pp share-count adjustment was added to a blend whose OE/share CAGR already embeds the share-count trend. Now it is applied to the three revenue components only (`growth_components_adjusted`, `share_adj_basis`). (2) **The v5.2 "basic-only shares = gap" rule was dead code**: a basic-only period fell through to `CommonStockSharesOutstanding` / dei cover-page counts and shipped a tier unflagged. Any non-diluted source in the last 3 FY is now `DATA_GAP:shares`, the flag names the fallback count so a filing override (10-K EPS note) is one step; older years may use the fallback for history (`shares_tag` column, `SHARES_FALLBACK` flag); dei counts match a period only within 90 days after its end. (3) **Debt stacked**: `LongTermDebt` (a total including current maturities) sat in the noncurrent list and was added to `DebtCurrent`. Total-debt tags are now a separate series used only when no noncurrent tag reports; short-term borrowings / commercial paper / lease-inclusive tags added; the basis is recorded per period (`debt_tag`, `net_debt_basis`); no debt tag at all raises `DEBT_TAGS_BLANK` instead of reading as net cash. (4) **IRR floor**: the terminal value used `max(r − g, 0.005)`, so an IRR below terminal growth + 0.5% could never be solved and names there (ZS, MDB, GFI's bear cases) carried fake figures. The Gordon value does not converge at r ≤ g (+inf now); a perpetuity growing at g has an IRR above g at any price, so the solver converges just above g and flags `IRR_AT_FLOOR` — read as "at most ~3%". (5) **IRR band + hurdle prices**: `irr_bear` / `irr_bull` / `tier_bear` / `tier_bull` (`TIER_BAND` flag when they differ — size to the bear end), weighted `iv_at_20` / `iv_at_25` = the Tier A / S prices, and the full 15-year `paths` / `growth_paths`. (6) **Tier F split**: `f_subtype` sbc_exceeds_cash vs no_cash_generation. (7) **Audit items closed in `forensic_pull.py`**: STALE_PASS1 printed after the flag list; routine 8-K items 2.02 / 7.01 counted as material; `pick()` took the first tag only. (8) **make_score** computes `model_fit` and `alert_eligible` (S/A alerts had been firing on misfits and override-only tiers). Consequence: every folder scored before 5.4 shows "Engine 5.3.x (pre-5.4 numbers)" on its page; its numbers are unchanged until its next engine run. The formula changes move g_base slightly for names whose OE/share CAGR sat in the middle of the blend, and can gap names whose last-3-FY share counts came from the outstanding / dei fallback — the DATA_GAP flag now says exactly which count was filed instead.
- **2026-10-14 — Engine v5.3.1: four bugs found by Codex's review of Stocks PR #1, all fixed the same day (Andrew: "fix all of them on same branch").** (1) **Monetary overrides were never FX-converted** — the FX pass converted filed series, then `load_overrides` values (declared in the reporting currency, read from the filing) were inserted verbatim into USD series; the sanity band also compared them against post-conversion values. Fix: `_override_usd()` converts capex/SBC overrides at the same period-end rate as the filed series (share counts never converted; no rate for a period → no fill, the gap stands), conversions are recorded in `fx_conversion.overrides_converted`, and the band anchors on the last filed value captured in its FILED unit before conversion. Proven exactly: a synthetic €50M SBC override on FER filled as $53.33M/$55.25M/$51.945M/$58.75M = €50M × each period's rate. (2) **make_score's median branch swallowed counterfactual replay failures** — `_run_json` returns None for timeouts/crashes/bad output as well as for a gate-fired replay, and v5.3 recorded null override impact and scored anyway whenever the override unblocked a gap (the TTM branch failed hard on the same condition). Fix: a None replay fails hard; null impact is recorded only when the replay actually returned JSON with a `data_gap` and no base. Verified in all three branches synthetically; STZ's shares-override scoring (the case the null path exists for) still works, and APP's registry entry reproduced bit-for-bit. (3) **period_series picked one unit per tag** — a tag with USD facts for some years and local-currency facts for others dropped the local-only years. Fix: units merge per period in preference order (USD, shares, USD/shares, then others), unit recorded per period. First live effect: BIDU — Baidu files some core periods CNY-only; they are now read and FX-converted instead of silently absent (its shares gap is unchanged). (4) **Mixed-currency detection scanned all history** — one stray historical second-currency fact disabled conversion for a filer single-currency today. Fix: eligibility is judged on the last-3-FY core facts (revenue/NI/OCF); exactly one recent core currency → convert it plus any stray-currency periods at their own rates; two or more → genuinely mixed, no conversion; none → fall back to the all-history set (the JD translations shape). The currency gate now uses one rule: a last-3-FY core period gaps iff it was filed non-USD and the FX pass did not convert it. Regression battery after the fixes: STZ base exact ($9.832657431878246), CCJ/GFI/JD and 13 other foreign names bit-identical, EC/BAP still currency-gapped, NMR still field-gapped. ## Method honesty
- This is a *screening* DCF: one standardized growth-fade model for every company so rankings are comparable. It is not a bespoke institutional model per name.
- Maintenance capex is estimated, never disclosed — hence the two definitions and a range mindset.
- Financials (banks/insurers) and REITs: owner's earnings / capex logic fits poorly. The agent must flag sector-model mismatch in `analysis.md` and grade confidence low rather than force a tier.
